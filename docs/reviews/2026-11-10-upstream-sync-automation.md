# Upstream synchronization automation assessment

Request: assess a 24-hour and Codex clean-post-commit workflow to merge upstream, resolve conflicts, commit and build only when the worktree is clean. Assessment only at this stage; no automation or hooks activated.

Observed: checkout desktop-improvements tracks origin/desktop-improvements. origin is renxotech/git-desktop; upstream is desktop/desktop. Local development and upstream/development both currently resolve to 2e756abd6cf65cfeafc24789c9d9892d86ef79af. Main HEAD 50d49f69a4. Checkout has separately owned, uncommitted date-based build changes; therefore a proposed run must skip it today.

Findings and dispositions:
- A1 accepted design requirement: clean Git status is not proof no chat is working. Use an isolated candidate worktree, one shared cooperative lock for sync/build/Codex writers, clean/status/branch/HEAD checks before starting and again under lock before promotion. External writers that ignore the lock remain a race; leave candidate unpromoted when exclusivity cannot be established. Include tracked/index/untracked files and submodule status; fail closed if checks cannot complete. Ignore ordinary ignored outputs, never stash/reset/clean user changes.
- A2 accepted design requirement: fetch explicit upstream/development into desktop-improvements, not the branch's default tracking ref origin/desktop-improvements. Freeze fetched and local SHAs. No upstream rewrite reconciliation without review.
- A3 accepted design requirement: daily timer plus a shared Codex commit-finalization entry point. Git hooks alone do not identify Codex-origin commits. The commit entry point should enqueue/coalesce work and return; never run recursive merges/builds inside post-commit. Exclude automation-created commits, deduplicate source/upstream pairs and use a bounded failure retry policy.
- A4 accepted design requirement: resolve explainable conflicts with focused validation; stop on ambiguous behavior changes, dependencies or policy. Candidate commit and exact-commit build must succeed before advancing user branch. Recheck clean/unchanged HEAD and branch before promotion; retain candidate and report failure rather than touching the original checkout. No automatic push or app launch. Preserve prior successful package and output to a unique version directory. Build only when source changed or the current source has no successful build; a daily no-change check need not rebuild.
- A5 accepted prerequisite, separate owner: script/build-local.ps1 still invokes vendor/yarn-1.21.1.js, which does not exist after npm migration. Its build helper also waits for GitDesktop to close unless NonInteractive; unattended automation must never prompt or terminate the running app. Reconcile with date-based build owner's changes and validate a complete npm build before enabling. Existing source validation is not a successful packaged build.
- A6 informational: available desktop automation API supports schedules; no local Codex commit event trigger is exposed. Official docs say local scheduled tasks require computer on/app running and desktop app events are unavailable. A daily task is feasible, exact commit triggering needs repository integration. Source: https://learn.chatgpt.com/docs/automations?surface=app .

Recommended next action if implementation requested: agree upstream/development and candidate-promotion policy; implement one reusable sync runner and Codex commit-finalization integration with disposable-Git tests, reconcile current build wrapper under its existing ownership, perform one complete trial, then enable daily schedule. All A1–A5 are proposed requirements/prerequisites, not accepted implementation backlog yet. No scheduled task/hook/background process/merge/fetch/commit/build started by this assessment.
