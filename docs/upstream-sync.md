# Daily and Codex post-commit integration

Authorized target: desktop-improvements in D:/code/git-desktop, source upstream/development (desktop/desktop). Never push, launch an app, force-update a branch, stash, reset or clean user changes. Missing checks or ambiguous conflicts stop the run. Configuration flags enable only for explicit true; no optional flags currently exist.

Every Codex writer in this checkout must honor the lock reported by `node script/upstream-sync.cjs status` before editing or committing. If its state directory contains `lock`, defer work until its owning sync run finishes. Clean status alone does not establish exclusivity against nonparticipating editors.

After a Codex-requested commit that leaves this checkout clean, run this procedure immediately. Integration-created commits never trigger another run. Coalesce requests while locked. Daily runs use the same procedure; dirty/busy/different-branch runs skip without changes. Do not retry failures in a loop.

1. Read the task ledger and inspect branch, status including submodules, active Git operations and active owners. If another writer/build is active, skip. Confirm upstream remote is https://github.com/desktop/desktop.git before fetching. Run `node script/upstream-sync.cjs prepare`. Dirty status or status errors fail closed. The runner takes a shared lock and creates an isolated candidate under the Git common directory, recording exact starting and upstream commits. No original checkout files are merged here.
2. Work exclusively in the reported candidate. Resolve explainable conflicts preserving local features and incoming contracts. Stop and report ambiguous product/policy changes. Review automatic merges too. Stage only integration changes; create a local merge commit if necessary. If already up-to-date and a successful exact-source receipt exists, abandon the candidate and skip rebuilding. Otherwise continue.
3. Prepare independent dependencies and submodules in the candidate using npm and git; never share writable build outputs with the original. Run TypeScript, focused tests covering conflicts and changed contracts, formatting/lint and an independent source assessment. Do not weaken tests to hide failures. Record commands and results in the run directory outside the candidate. No source edits while tests/build run. Commit fixes before final build.
4. Build the exact clean candidate using `build.cmd -NonInteractive -NoLaunch`. Preserve the prior successful package; the candidate has its own dist folder. A failure retains this candidate and its logs. Do not kill the running app. Check final HEAD and clean status again; verify executable and build-info.json identify the tested source. Write `verified.json` in the reported run directory containing head (full candidate HEAD), tests: true and build: true only after all checks pass. This receipt is an agent assertion backed by retained logs, not independent proof.
5. Run the original checkout's `node script/upstream-sync.cjs finish`. It verifies candidate ancestry, receipt, clean original checkout, same branch and unchanged starting HEAD before a fast-forward. Cooperative lock remains held through promotion. If any condition fails, retain the candidate and report. Do not reset or overwrite the original.
6. On any failed run, call `node script/upstream-sync.cjs abandon` only for your own recorded active run to retain the candidate/evidence and release the lock. Never delete a foreign/stale lock automatically: inspect ownership and recover explicitly. Report output location, commits, validation and any blockers. No further automatic retries until the next scheduled run or a new user commit.

The daily schedule requires this computer and desktop app running. Post-commit behavior is a Codex project instruction, not an OS Git hook: it applies to commits made by participating Codex chats, not external Git clients. Existing chats must observe updated instructions. Uncooperative external writers remain a concurrency limitation; skip if exclusive ownership cannot be established.
